# Що додавати далі (порядок: геометрія → згущення → солвер)

Принцип: кожен етап закінчується «заморожуванням» (еталонні тести) і не ламає попередніх. Етапи залежать так:
**G** (геометрія) → **R** (згущення) → **S** (солвер), але **Q** (якість/придатність) пронизує всі.
Пункти F* — із [FIX_LIST.md](FIX_LIST.md), їх треба робити паралельно (особливо F11–F20 до будь-яких користувачів).

## G — потужне формування геометрії (CAD-редактор)
Мета: не гірше платних HyperMesh/ANSA/ICEM у профілі криволінійних гексів, але з перевагою «геометрія = елемент».

| ID | Фіча | Навіщо / деталі |
|---|---|---|
| G1 | **Блочне структурування** (blocking): користувач малює «грубі» блоки, система будує O-grid/«метелик» усередині круглих перерізів | прибирає кутові вироджені куби циліндра/кулі; вимагає не-ґраткових зв'язків між гранями (вузли `HexLink` вже мають явні сусідства) |
| G2 | **Проєкція вузлів на поверхню/криву** (STL/STEP): вузол або ребро «прилипає» до поверхні, ручні інструменти без автоматики | найближча точка на фасетній геометрії зараз є лише як еталон; потрібен ручний «snap/project» і візуальна відстань |
| G3 | **Операції над кубами**: дзеркало, масив, поворот, масштаб, extrude/revolve грані, sweep вздовж кривої, offset-шари (оболонки) | основа швидкого моделювання; кожна — команда з undo |
| G4 | **Парамеричні тіла з історією** (дерево побудови): зміна параметра перебудовує вниз за ланцюжком | редагування радіуса/товщини без ручної переробки |
| G5 | **Шари як перші громадяни**: ім'я, колір, матеріал, видимість; операції «товщина шару», «додати шар зовні/всередину» | багатошарові тіла (шари вже є як групи кубів; шаблон зуба прибрано — не був схожий на зуб) |
| G6 | **Порожнини й отвори** як операція (камера пульпи, канали): прибрати куби + згладити межу | зуб із пустотою, труба, корона |
| G7 | **Імпорт/експорт**: STEP/IGES (геометрія-орієнтир), `.inp` (Abaqus/CalculiX C3D20), `.bdf`, VTK; експорт у ваш старий формат | сумісність з ринком; F7 |
| G8 | **Точна геометрія ребер**: дуга замість параболи (раціональні елементи/NURBS) як опція | «ідеальне коло»; дослідити IGA, Bézier-екстракцію |
| G9 | **Вимірювання й перевірки**: об'єм, площа, центр мас, найкоротше ребро, відстань до STL, перетини куби-куби | перед розв'язком |
| G10 | Продуктивність: сотні тисяч кубів у редакторі (інстансинг, LOD, Worker-розрахунок геометрії) | масштаб |

## Q — монітор придатності геометрії до солвера (професійний)
Уже є: scaled Jacobian, відношення якобіанів, aspect, перекіс; оцінки Excellent…Invalid; підсвітка на сцені; попередження про погану якість і контраст жорсткостей.
Додати:
- **Q1** Гістограми метрик, фільтр «показати лише Poor/Invalid», перехід до куба з панелі, закріплена легенда порогів.
- **Q2** Метрики «до і після» кожної команди (піктограма в історії: якість погіршилась) та **блокування розрахунку** з поясненням і швидким виправленням.
- **Q3** **Прогноз похибки до розрахунку**: апріорний індикатор (розмір елемента / кривизна поверхні, `h/R`), **апостеріорний ZZ** після розрахунку — на сцені як поле.
- **Q4** Перевірка **конформності й сполучності**: висячі вузли, дублікати вузлів, ізольовані частини, перекриття, відсутність закріплення (є частково).
- **Q5** **Обумовленість**: оцінка числа обумовленості (Lanczos із CG), попередження про шкалу (мм/м), про контраст E.
- **Q6** Звіт придатності (JSON/PDF) для проєкту — єдина «сторінка здоров'я» сітки.

## R — локальне згущення (інтеграція, пізніше)
Вимоги до контракту — щоб підключилось легко:
1. **Інтерфейс** `IRefiner`: `Refine(HexMesh, RefinementRequest) → RefinementResult { HexMesh Fine, IReadOnlyList<Constraint> Hanging, ParentMap }`.
2. **Сітка зберігає дерево**: `Hex20.ParentId` + рівень + шаблон (T1/T2/T4) — поле вже є, потрібен шар персистентності й undo.
3. **Солвер приймає обмеження (MPC)**: у `Solvix.Fem` додати `ConstraintSet` (master–slave/елімінація) для висячих вузлів — F5/S-розв'язувач має це підтримувати. Альтернатива «propagation» (без висячих вузлів) — як перший крок, як у вашому дослідженні (`project3_research`).
4. **Ідеальний світ** лишається ґраткою: згущення не міняє геометрію (вузли на ізопараметричній поверхні батька), тож `Σφᵢxᵢ` батька = нова сітка.
5. **Замкнені кільця**: `MarkPass` має бути виправлений (довільний старт у замкненому ланцюгу, парна довжина) — узгоджено раніше, зробити разом із R.
6. **Критерій**: ZZ-індикатор (Q3) → список кубів на ділення → цикл розв'язок–оцінка–згущення з обмеженням на рівні.
7. Тести: конформність після кожного шаблону, збереження об'єму/геометрії, збіжність.

## S — солвер до рівня «показує реальні результати»
| ID | Фіча | Примітка |
|---|---|---|
| S1 | F3–F5 (SPR, нестисливість, розв'язувач) | першочергово |
| S2 | **Навантаження**: власна вага/об'ємні сили, точкові сили, тракція (вектор) на грані, температура (термоделформація), перенесення тиску на криву | розширюване через `LoadCase` |
| S3 | **Опори**: ненульові переміщення, симетрія (нормальна компонента), ролик, пружна основа | замість «усі вузли грані» |
| S4 | **Анізотропні матеріали** + локальні осі елемента (емаль/дентин) | `Material.D` готовий |
| S5 | Модальний аналіз (власні частоти), лінійна стійкість | розширення збирання `M` |
| S6 | **Нелінійності**: геометрична (великі деформації), матеріальна (пластичність, гіперпружність для гуми/м'яких тканин), контакт | великий обсяг; після S1–S4 |
| S7 | Післяобробка: головні напруження, сили реакцій, лінійні перерізи, зонд у точці, експорт у VTK, порівняння двох розрахунків | вектори/перерізи з вашого вʼюера |
| S8 | **Автоматична верифікація проти CalculiX/Code_Aster** (F7) | довіра до результатів |
| S9 | Продуктивність: пам'ять CSR, паралельний matvec, Pardiso/CHOLMOD чи власний sparse Cholesky, GPU-варіант | 10⁶ DOF |
