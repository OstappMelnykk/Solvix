# Корисні вимоги зі старого ТЗ (MastersDegreeProject)

Витяг з `ТЗ.md` старого проєкту (32 КБ). Лишено тільки те, що стосується алгоритму та сітки й не суперечить Solvix. Нумерація збережена, щоб можна було звіритися з оригіналом. Усе, що стосується UI старого фронтенду, авторизації, вкладок, перекладу й налаштувань кольорів, не береться.

## 1. Вимоги до алгоритму локального згущення

| № | Вимога |
|---|---|
| A1 | Елементи вільної форми й довільного положення: без прив'язки до координатної сітки, координати ненормовані |
| A2 | Рядки, стовпці й шари визначаються топологічно (через сусідів), а не за координатами |
| A3 | 2-refinement: hex ділиться на 8 дочірніх |
| A4 | Парування рядків/стовпців/шарів глобально детерміноване (even-odd: 0-1, 2-3, ...); якщо кількість непарна, останній лишається без пари |
| A5–A7 | Проходи I (X), J (Y), K (Z): маркування вузлів на межі пар, далі шаблони T1/T2 (у 3D ще T3 за статтею) |
| A8 | Expand між проходами: до активної зони додаються нові refined-елементи |
| A11 | Hex з усіма 8 маркованими вузлами ігнорується (не рафінується) |
| A12 | nX, nY, nZ ≥ 2 (A15) і однакові для всіх виділених елементів у цьому запуску; для наступного запуску задаються нові |
| A13 | Після кожного запуску немає висячих вузлів |
| A14 | Сітка конформна: кожне ребро ділиться однаково з обох боків |
| A16 | Повторне згущення дочірніх елементів: спочатку node propagation, якщо неможливо, то deep traversal (**у Solvix propagation не використовується**, див. `project/algorithms/ALGORITHM.md`) |

## 2. Вимоги якості сітки для МСЕ

Значення за Knupp 2003 і Verdict (Sandia). **Не перевірені нами**, джерела не читано. Звіряти з `project/research/02-quality`.

| Метрика | Рекомендоване | Граничне |
|---|---|---|
| Aspect ratio (3D hex) | < 5:1 | < 10:1 |
| Scaled Jacobian (3D hex) | > 0.5 | > 0.2 |

## 3. Інтеграція згущення (покроковий режим)

| № | Вимога |
|---|---|
| R1–R2 | Виділити елементи, задати nX, nY, nZ |
| R3–R5 | Preview проходу без застосування, потім Apply для X, Y (і Z) |
| R6–R8 | Step Mode: зупинка на кожному кроці, пояснення тексту, підсвітка активних вузлів, ребер і нових елементів |
| R9 | Кроки назад: зберігати 1 snapshot початкового стану й список легких подій (MarkNode, ApplyTemplate). Prev Step = snapshot + повтор перших K подій. Пам'ять O(events), а не O(кроки × розмір сітки) |
| R10 | Cancel: відкат до стану до запуску |
| R11 | Повторне згущення дочірніх елементів, параметри n задаються заново |

## 4. Згладжування

| № | Вимога |
|---|---|
| S1 | Старе рішення: Combined Taubin+Area (λ=0.5, μ=−0.53, α=0.6, β=0.4, 10 ітерацій). **У Solvix рішення інше**, див. `project/research/03-smoothing` |
| S3 | Quality guard: після кожної ітерації перевіряти SJ ≥ 0.2; якщо елемент, що мав SJ ≥ 0.2, опустився нижче, ітерацію відкинути |
| S4 | Показувати метрики до й після: SJ min/avg, AR max |
| S6 | Вузли границі й обмежень (`IsBoundary`, `IsConstraint`) не рухаються |

## 5. Режими й редагування

| № | Вимога |
|---|---|
| G7, M6 | Два режими: **Editing** (додавати/видаляти/рухати hex, snap, undo) і **Refined** (лише перегляд, згладжування, експорт). Refined→Editing скасовує все згущення повністю, тоді користувач редагує й запускає згущення знову. Так висячі вузли неможливі, а ціна O(n) |
| G6 | Snap: вузол, що наблизився до вузла іншого елемента, зливається з ним (спільний вузол), поріг налаштовується |
| G8, M4 | Спільні вузли оновлюються синхронно у всіх hex, яким вони належать |
| G10 | Snap вузлів hex до грані іншого hex автоматично встановлює FaceSlot (сусідство) |
| G11 | Видалення hex оновлює FaceSlots сусідів |
| M1, M3 | Тягнути можна тільки кутові й серединні вузли Level 0; дочірні елементи власного drag не мають. Вузлів у hex 20: 8 кутових + 12 серединних |
| M2 | При перетягуванні кутового вузла ізопараметричне оновлення стосується лише листків цього батька |
| M5 | Для згущення вибираються листки, видимі зовні; внутрішні (повністю оточені) не виділяються |
