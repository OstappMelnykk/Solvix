## Основні поняття

**Елемент сітки** — це шестигранник (гексаедр, гекс). Він має 8 вузлів, 12 ребер і 6 граней. Сам по собі є атомарною одиницею сітки.

**Вузол** — точка у куті шестигранника. Кожен вузол може бути спільним для кількох гексів (типово для 8 гексів у внутрішній точці сітки). Вузол сам по собі не є елементом.

**Грань** — квадратна поверхня що є спільною між двома сусідніми гексами. Грань = 4 вузли + 4 ребра. Через одну грань гекс контактує рівно з одним сусідом.

**Ребро** — відрізок між двома сусідніми вузлами. Ребро спільне для 4 гексів у внутрішній точці сітки.

Аналогія з 2D:

| | 2D | 3D |
|--|--|--|
| Елемент | Чотирикутник (quad, 4 вузли, 4 ребра) | Шестигранник (hex, 8 вузлів, 12 ребер, 6 граней) |
| Вузол | Точка в куті квада | Точка в куті гекса |
| Спільна межа між елементами | Ребро (2 вузли) | Грань (4 вузли) |

## Нумерація вузлів гексаедра і система координат

Стандартна нумерація вузлів гексаедра що використовується у цьому документі і у всіх html-візуалізаціях:

```
Вигляд збоку (вісь Z направлена "вглиб"):

    v3----v2             v7----v6
    |      |    Z+  →   |      |
    v0----v1             v4----v5

  Передня грань (z=0)   Задня грань (z=1)
```

Скорочення для назв кутів: **B**ottom/Top + **L**eft/Right + **F**ront/Back:

| Код | Назва | Вузол | Координати |
|-----|-------|-------|------------|
| BLF | Bottom-Left-Front | v0 | (0, 0, 0) |
| BRF | Bottom-Right-Front | v1 | (1, 0, 0) |
| TRF | Top-Right-Front | v2 | (1, 1, 0) |
| TLF | Top-Left-Front | v3 | (0, 1, 0) |
| BLB | Bottom-Left-Back | v4 | (0, 0, 1) |
| BRB | Bottom-Right-Back | v5 | (1, 0, 1) |
| TRB | Top-Right-Back | v6 | (1, 1, 1) |
| TLB | Top-Left-Back | v7 | (0, 1, 1) |

Три осі і напрямки:

| Вісь | Напрямок | Від → До |
|------|----------|----------|
| I (X) | Left → Right | v0 → v1 |
| J (Y) | Bottom → Top | v0 → v3 |
| K (Z) | Front → Back | v0 → v4 |

Сусіди гекса: **Left** (−I), **Right** (+I), **Bottom** (−J), **Top** (+J), **Front** (−K), **Back** (+K).

## Поняття шарів (layers) та проходів (passes)

### Шар (layer)

Тривимірна сітка розміром N_I × N_J × N_K містить N_I × N_J × N_K гексаедрів. Їх розбивають на **шари** по кожній осі:

**I-шар (I-layer)** — сукупність усіх гексів з однаковим I-індексом. Це плоский "зріз" сітки перпендикулярний до осі I. Якщо сітка N_I × N_J × N_K, то є N_I I-шарів, кожен розміром 1 × N_J × N_K.

**J-шар (J-layer)** — аналогічно, усі гекси з однаковим J-індексом. Зріз перпендикулярний до осі J. Є N_J шарів.

**K-шар (K-layer)** — зріз перпендикулярний до осі K. Є N_K шарів.

Фізична аналогія: уяви батон хліба. Якщо різати вертикально по X — отримуєш I-шари. Якщо різати горизонтально по Y — J-шари. Якщо різати по глибині Z — K-шари. Три незалежних набори "скибочок".

```
Сітка 4×3×2 (N_I=4, N_J=3, N_K=2):

  J=2  ┌────┬────┬────┬────┐
       │    │    │    │    │  ← один K-шар (K=0)
  J=1  ├────┼────┼────┼────┤     з 4×3 гексів
       │    │    │    │    │
  J=0  ├────┼────┼────┼────┤
       │    │    │    │    │
       └────┴────┴────┴────┘
        I=0  I=1  I=2  I=3

  ↑ I-шар I=1: вертикальний стовпець 1×N_J×N_K = 1×3×2 гексів
```

### Прохід (pass)

**I-pass** — повна обробка всіх пар I-шарів: маркування вузлів і застосування шаблонів у I-напрямку.

**J-pass** — аналогічна обробка по парах J-шарів.

**K-pass** — аналогічна обробка по парах K-шарів.

Проходи виконуються **послідовно**: спочатку I-pass, після нього Expand, потім J-pass, після нього Expand, потім K-pass.

## Algorithm 1 — Three-Dimensional Two Refinement

```
INPUT:  Cartesian grid G, множина шестигранників M ⊆ G для рефайнменту
OUTPUT: Локально згущена конформна сітка

1. Enumerate(G)
2. M ← IdentifyMarkedElements(G)
3. for each direction d ∈ {I, J, K} do
4.     MarkNodes(G, M, d)          (§4.3, §4.6, §4.8)
5.     ApplyTemplates(G, M, d)     (§4.4, §4.7, §4.8)
6.     M ← Expand(M)              (§4.5, §4.8)
7. end for
```

---

## §4.1 — Enumerate

### Що нумерується

Кожному **шестиграннику** у сітці G присвоюється трійка цілочисельних індексів **(i, j, k)** починаючи з 0:
- i ∈ {0, …, N_I − 1}
- j ∈ {0, …, N_J − 1}
- k ∈ {0, …, N_K − 1}

Це пряма аналогія з 2D де кожному квадратнику присвоювалась пара (i, j). У 3D додається третій індекс k для K-напрямку.

### Even-odd парування

По кожному напрямку шари розбиваються на **пари (парний, непарний)**:

```
I-шари: (I=0, I=1), (I=2, I=3), (I=4, I=5), ...
J-шари: (J=0, J=1), (J=2, J=3), (J=4, J=5), ...
K-шари: (K=0, K=1), (K=2, K=3), (K=4, K=5), ...
```

Кожна пара обробляється разом. Парування є **глобальним і фіксованим** — починається завжди з 0 і не залежить від того який підмножина M вибрана для рефайнменту. Це та сама логіка що й у 2D де рядки і стовпці нумерувались від 0 і парувались попарно.

### Процесори та паралельна обробка

На відміну від 2D де паралельність не обговорювалась, Owen et al. явно розглядають розподілений 3D випадок. Причина: 3D сітки значно більші (мільйони гексів) і обробляються на кількох процесорах.

**Як розподіляється робота:** сітка G розбивається між процесорами по блоках. Кожен процесор обробляє свій підрегіон G.

**Проблема:** щоб алгоритм давав однаковий результат незалежно від кількості процесорів, парування (even-odd) повинне бути **глобально консистентним**. Тобто всі процесори повинні погоджуватись: який I-шар "парний" а який "непарний" — навіть якщо межа між двома процесорами проходить прямо між I=2 і I=3.

**Рішення:** початкові індекси кожного процесора визначаються глобально (рис. 11 статті). Кожен процесор знає глобальний зсув своїх індексів і правильно продовжує парування.

**Комунікація:** мінімальна — тільки на межах між процесорами, де потрібно знати статус сусідніх гексів.

### Відмінності від 2D: Enumerate

| | 2D | 3D |
|--|--|--|
| Індекси елемента | (i, j) | (i, j, k) |
| Напрямків | 2 (X, Y) | 3 (I, J, K) |
| Пар шарів | по X і по Y | по I, по J і по K |
| Паралельність | не обговорюється | явно описана (fig. 11) |

## §4.2 — IdentifyMarkedElements

M — множина шестигранників які вибрані для рівномірного рефайнменту. Кожен елемент з M буде гарантовано поділений рівномірно на 8 дочірніх шестигранників. Сусідні елементи поза M що межують із зоною рефайнменту отримують шаблони переходу для збереження конформності (без висячих вузлів).

---

## §4.3 — Mark nodes (I direction)

### Що таке I-pass фізично

Уяви сітку гексів. I-pass дивиться на **вертикальні "стіни"** між I-шарами — кожна така стіна є гранню (face) між шаром i і шаром i+1. Алгоритм проходиться по парах (0,1), (2,3), ... і для кожної пари перевіряє: чи потрібно маркувати вузли стінки між ними?

### Алгоритм маркування

```
for кожної пари I-шарів (i_пар, i_непар) де i_непар = i_пар + 1 do
    for кожної позиції (j, k) do
        if елемент (i_пар, j, k) ∈ M  АБО  елемент (i_непар, j, k) ∈ M then
            позначити всі 4 вузли спільної грані між шарами i_пар і i_непар
        end if
    end for
end for
```

### Що відбувається якщо умова виконана

Спільна грань між I-шарами i_пар і i_непар у позиції (j, k) — це **прямокутна грань з 4 вузлами** (у одиничному гексі: вузли v1, v2, v5, v6 для правої I+ грані). Маркуються **всі 4 вузли** цієї грані (рис. 10(b) статті).

Маркований вузол може належати кільком гексам. Тому ефект поширюється на всіх сусідів що мають цей вузол:

```
Один гекс у M (позиція (i_пар, j, k)):
→ Маркуються 4 вузли I-грані
→ Ці 4 вузли належать кільком різним гексам
→ Кожен гекс накопичує позначені вузли
→ Після завершення циклу: кожен гекс отримує шаблон за кількістю своїх позначених вузлів:
   - 4 на одній грані → T4 (гекс прямо в парі → найпростіший поділ)
   - 2 на одному ребрі → T2 (гекс збоку в J або K напрямку)
   - 1 вузол         → T1 (гекс на діагоналі пари)
```

Конкретний приклад (рис. 10 статті): один елемент у M в центрі сітки:
- 2 безпосередніх сусіди в I-напрямку → **T4**
- 4 сусіди в J і K напрямках → **T2**
- 4 кутових сусіди → **T1**

### Відмінність від 2D

У 2D X-pass маркував **2 вузли** (ребро між рядками). У 3D I-pass маркує **4 вузли** (грань між шарами). Через це у 3D вже після I-pass можливий шаблон T4 — чого у 2D не було (там з I-pass виходив тільки T1 або T2).

### Перехід до наступної ітерації і наступного проходу

Після завершення всіх пар (i_пар, i_непар) I-pass завершено. Далі:

1. **ApplyTemplates (I)** — кожен гекс з ≥1 маркованим вузлом отримує шаблон (§4.4).
2. **Expand (M)** — до M додаються всі нові дочірні елементи (§4.5).
3. **J-pass починається** — алгоритм повністю аналогічний I-pass але по парах J-шарів.
4. Після J-pass: Expand → K-pass → кінець.

Кожен наступний прохід враховує вузли що з'явилися в попередньому — тому J-pass може маркувати як вихідні вузли сітки, так і нові вузли що вставив I-pass.

## §4.4 — ApplyTemplates (I direction)

Кожен гекс з хоча б одним маркованим вузлом отримує один із чотирьох шаблонів (рис. 5 статті):

| Кількість позначених вузлів | Шаблон | Дочірніх (n=2) |
|-----------------------------|--------|----------------|
| 1 | T1 | 4 |
| 2 (на одному ребрі) | T2 | 3 |
| 3 (L-форма на одній грані) | T3 | 3D тільки |
| 4 (уся одна грань) | T4 | 2 |

### T1 (1 позначений вузол)

**Що маркується.** Рівно один вузол гекса — один із 8 кутів. Назвемо його Vi.

**Ідея.** Від позначеного кута Vi будуються концентричні "оболонки" — масштабовані копії батьківського гекса. Кожна оболонка менша за попередню і центрована на Vi. Між сусідніми оболонками утворюється "шар" із трьох трапецієподібних дочірніх гексів (X-hex, Y-hex, Z-hex). Найвнутрішніша оболонка — кутовий куб.

**Нові вузли (для n=2, Vi = v0 = BLF = (0,0,0)):**

| Новий вузол | Позиція | Напрямок від Vi |
|-------------|---------|-----------------|
| M₁ | mid(v0, v1) = (½,0,0) | X-ребро |
| M₃ | mid(v0, v3) = (0,½,0) | Y-ребро |
| M₄ | mid(v0, v4) = (0,0,½) | Z-ребро |
| M₂ | mid(v0, v2) = (½,½,0) | XY грань-діагональ |
| M₅ | mid(v0, v5) = (½,0,½) | XZ грань-діагональ |
| M₇ | mid(v0, v7) = (0,½,½) | YZ грань-діагональ |
| M₆ | mid(v0, v6) = (½,½,½) | просторова діагональ = центр гекса |

Разом: **7 нових вузлів** для n=2.

**Дочірні елементи (4 штуки для n=2):**

| Дочірній | Вузли | Геометрія |
|----------|-------|-----------|
| Кутовий куб | [v0, M₁, M₂, M₃, M₄, M₅, M₆, M₇] | Менший гекс у куті Vi, розмір ½ від батька |
| X-hex | [M₁, v1, v2, M₂, M₅, v5, v6, M₆] | Трапеція: зовн. грань {v1,v2,v5,v6} велика, внутр. {M₁,M₂,M₅,M₆} вдвічі менша |
| Y-hex | [M₃, M₂, v2, v3, M₇, M₆, v6, v7] | Трапеція: зовн. грань {v2,v3,v6,v7} велика, внутр. {M₂,M₃,M₇,M₆} менша |
| Z-hex | [M₄, M₅, M₆, M₇, v4, v5, v6, v7] | Трапеція: зовн. грань {v4,v5,v6,v7} велика, внутр. {M₄,M₅,M₇,M₆} менша |

**Геометрія у словах.** Стоїш у позначеному куті Vi і дивишся на гекс. Три ребра виходять з Vi у трьох напрямках (X, Y, Z). Три грані виходять з Vi (XY-грань, XZ-грань, YZ-грань). Центр гекса — по просторовій діагоналі. Нові вузли вставляються рівно посередині кожного з цих відрізків (для n=2). Вони утворюють меншу версію гекса всередині (scale ½) — це "внутрішня оболонка". Між зовнішніми 8 вузлами і внутрішніми 7+Vi — три трапецієподібних гекси, кожен "сторожить" одну зовнішню грань (X+, Y+, Z+). Внутрішня оболонка стає кутовим кубом. Разом: 4 дочірніх.

**Загальна кількість дочірніх для довільного n:** 3n − 2 (n оболонок × 3 трапеції − 2 + 1 кутовий куб = 3(n−1) + 1).

Детальний опис з параметром n — у `algorithm-3d-improvements.md`.

### T2 (2 позначених вузли на одному ребрі)

**Що маркується.** Рівно два вузли що утворюють одне ребро гекса. Ребер у гекса 12 — T2 можливий для будь-якого з них. Назвемо позначені вузли Va і Va+1.

**Ідея.** Позначене ребро Va–Va+1 є спільним ребром двох граней гекса — назвемо їх "лівою" і "правою" (за кінцями ребра). Кожна з цих двох граней розглядається як 2D квад де позначений кут — відповідний кінець ребра (Va або Va+1). До кожної такої грані застосовується **2D T1 шаблон**: вставляються E1, E3, D-точки. D-точка — це центр грані. Потім відповідні 2D-квади двох граней з'єднуються між собою в 3D гекси. Результат: 3 дочірніх гексаедри.

**Нові вузли (для n=2, позначене ребро v0–v1, тобто X-ребро BLF–BRF):**

Позначене ребро лежить на двох перпендикулярних гранях:
- **Ліва грань** (x=0): квад {v0, v3, v7, v4} із позначеним кутом Va = v0
- **Права грань** (x=1): квад {v1, v2, v6, v5} із позначеним кутом Va+1 = v1

На кожній грані застосовується 2D T1 — вставляється 3 нових точки (E1, E3, D):

| Новий вузол | Позиція | Роль | Грань |
|-------------|---------|------|-------|
| Ma | mid(v0, v3) = (0, ½, 0) | E1 на лівій грані (Y-ребро від v0) | Ліва (x=0) |
| Mc | mid(v0, v4) = (0, 0, ½) | E3 на лівій грані (Z-ребро від v0) | Ліва (x=0) |
| Ce_L | center{v0,v3,v7,v4} = (0, ½, ½) | D — центр лівої грані | Ліва (x=0) |
| Mb | mid(v1, v2) = (1, ½, 0) | E1 на правій грані (Y-ребро від v1) | Права (x=1) |
| Md | mid(v1, v5) = (1, 0, ½) | E3 на правій грані (Z-ребро від v1) | Права (x=1) |
| Ce_R | center{v1,v2,v6,v5} = (1, ½, ½) | D — центр правої грані | Права (x=1) |

Разом: **6 нових вузлів** для n=2 (4 на ребрах + 2 центри перпендикулярних граней).

**2D T1 на кожній грані (розріз по x=0 і x=1):**

```
Ліва грань (x=0) — квад [v0, v3, v7, v4], Vi = v0:
    v3(0,1,0) ----Ma(0,½,0)---- v0(0,0,0)
        |         Ce_L(0,½,½)      |
    v7(0,1,1) ----         ---- Mc(0,0,½)
                                v4(0,0,1)

  T1 дочірні квади на лівій грані:
    1. Кутовий: [v0, Ma, Ce_L, Mc]
    2. Y-квад:  [Ma, v3, v7, Ce_L]
    3. Z-квад:  [Mc, Ce_L, v7, v4]
```

Аналогічно на правій грані (x=1) із Vi = v1: {Mb, Md, Ce_R} замість {Ma, Mc, Ce_L}.

**Дочірні гекси (3 штуки для n=2):**

Кожен 3D дочірній — це з'єднання відповідного 2D-квада лівої грані з відповідним 2D-квадом правої:

| Дочірній | Вузли | Геометрія |
|----------|-------|-----------|
| Кутовий гекс | [v0, v1, Mb, Ma, Mc, Md, Ce_R, Ce_L] | Містить позначене ребро v0–v1; займає кут (y<½, z<½) |
| Y-гекс | [Ma, Mb, v2, v3, Ce_L, Ce_R, v6, v7] | Крило в Y+ напрямку від кутового; займає (y>½, z<½) |
| Z-гекс | [Mc, Md, Ce_R, Ce_L, v4, v5, v6, v7] | Крило в Z+ напрямку від кутового; займає (y<½, z>½) |

**Геометрія у словах.** Стоїш у одному кінці позначеного ребра (Va=v0) і дивишся через гекс на другий кінець (Va+1=v1). Навколо тебе — ліва грань гекса, а навколо Va+1 — права. Обидві грані ділять себе як 2D T1: кожна розбивається на кутовий квад + два крила (по Y і по Z). З'єднуєш квади попарно: два кутових квади → кутовий гекс (містить позначене ребро), два Y-крила → Y-гекс, два Z-крила → Z-гекс. Разом: 3 дочірніх гексаедри.

**Зв'язок з 2D.** Кожна з двох граней перпендикулярних до позначеного ребра при розгляді окремо є точним 2D T1-шаблоном де позначений кут = кінець позначеного ребра. Таким чином T2 в 3D = "два 2D T1 з'єднані".

**Якість.** Scaled Jacobian ≥ 0.7 для рівномірної сітки. Детальна геометрія показана в `T2.html`.

**Загальна кількість дочірніх для довільного n:** 2n − 1.

### T3 (3 позначених вузли L-формою на одній грані)

T3 — виключно тривимірний шаблон (у 2D відсутній). 3 позначених вузли утворюють L-форму на одній грані: три з чотирьох кутів грані позначені, четвертий ні.

T3 корисний для захоплення угнутих (concave) областей. Формується злиттям двох суміжних T2: вузли двох сусідніх T2 зливаються парами, утворюючи L-форму (рис. 12 статті).

Важливо: два суміжних T3 несумісні — вирішується підвищенням одного до T4 (§4.9, умова 2).

### T4 (4 позначених вузли на одній грані)

**Що маркується.** Всі 4 вузли однієї грані. Це найпростіший і найякісніший шаблон.

**Геометрія.** Одна серединна грань вставляється паралельно до позначеної. Вона ділить гекс рівно на 2 дочірніх шари однакового розміру. Дочірні — рівні паралелепіпеди (або пропорційні до батька). Scaled Jacobian ≈ SJ батька.

**Загальна кількість дочірніх для довільного n:** n (n рівних шарів).

**Зв'язок з 2D.** T4 у 3D — пряма аналогія 2-template у 2D: маркована грань у 3D відповідає маркованому ребру у 2D; поділ на 2 шари у 3D відповідає поділу на 2 смуги у 2D.

**Зв'язок між шаблонами.** Кожна грань 3D гекса є квадом і відповідає 2D шаблону. Набір {T1, T2, T3, T4} є **повним** за обмеження маркування на кожні два шари.

## §4.5 — Expand (після I-pass)

До M додаються всі елементи що були щойно рафіновані в I-pass (рис. 10(e)). Це розширює зону рефайнменту перед J-pass і гарантує що J-pass застосовує шаблони лише до ще нерафінованих елементів — контролюється якість і градієнт розмірів.

## §4.6 — Mark nodes (J direction) + Node Propagation

### Базове маркування

J-pass повторює аналогічну процедуру в J-напрямку по парах J-шарів:

```
for кожної пари J-шарів (j_пар, j_непар) де j_непар = j_пар + 1 do
    for кожної позиції (i, k) do
        if будь-який елемент що межує з цією J-гранню ∈ M then
            позначити 4 вузли спільної J-грані між j_пар і j_непар,
            включаючи нові внутрішні вузли від I-рефайнменту
        end if
    end for
end for
```

Ключова відмінність від I-pass: тепер на J-гранях можуть бути **нові вузли** що з'явились після T1, T2, T4 поділів під час I-pass. Ці внутрішні вузли теж включаються до маркування.

### Node Propagation

Propagation виконується коли алгоритм (незалежно від того який це прохід — I, J чи K) намагається маркувати вершини гекса H який вже був поділений шаблоном. Не має значення на якому проході відбувся поділ і на якому проході відбувається маркування — важливий лише сам факт що H вже замінений дочірніми елементами.

**Топологія сітки — фундаментальне розуміння.**
Геометрія батьківського елемента що містить дочірні — це не набір ізольованих гексів, а **єдина спільна геометрія з графовою структурою**. Вузли не дублюються: один і той самий вузол може бути спільним для кількох дочірніх гексів одночасно. Наприклад після T1-поділу з Vi=v0 вузол M6=(½,½,½) входить до всіх чотирьох дочірніх гексів одразу — Corner, X-hex, Y-hex і Z-hex. Маркуючи M6 — алгоритм маркує цей вузол у всіх цих елементах одночасно. Алгоритм оперує вузлами сітки, а не вузлами окремих елементів.

**Властивості батьківських шаблонів для розуміння propagation.**
Після T1-поділу три грані H мають внутрішні точки (примикають до Vi) — **брудні**, три інших — чисті. Після T2-поділу грані що не містять жодного кінця позначеного ребра — чисті.

**Коли потрібний propagation.**
Коли батько поділений T1/T2 і деякі його базові вузли знову маркуються для застосування шаблонів у наступному проході.

---

#### Універсальний алгоритм propagation

Нехай батьківський гекс H поділений шаблоном **T** (T1 або T2) з параметром n. Vp — множина базових вузлів батька що маркуються поточним проходом.

**Shell-функція (залежно від типу батька):**

| Тип батька | Shell(scale)[k] | Цільовий елемент |
|-----------|----------------|-----------------|
| T1 (кут Vi) | масштабована копія батька центрована на Vi | Corner-hex |
| T2 (ребро Va–Vb) | трубка вздовж Va–Vb, масштабована в Y і Z | Edge-hex |

**Ланцюжок для кожного вузла Vp з shell-індексом k:**

```
chain(Vp) = [ shell( (n−j)/n )[k]  для j = 0, 1, ..., n−1 ]
```

Рухається від зовнішньої межі батька (j=0, scale=1) до цільового елемента (j=n−1, scale=1/n).

**Множина маркованих вузлів:**

```
P = ⋃ chain(Vp)  для кожного Vp ∈ Vp-множини
```

**Класифікація кожного дочірнього C за кількістю його вузлів у P:**

| Вузлів P у C | Шаблон |
|-------------|--------|
| 0 або 8 | none (не ділимо) |
| 1 | T1 |
| 2 на одному ребрі | T2 |
| 2 діагональних на грані | T4 (§4.9 умова 1) |
| 4 на одній грані | T4 |

**Режими вибору Vp:**

| Режим | Vp-множина |
|-------|-----------|
| V1 | один довільний базовий вузол |
| V2 | два вузли що утворюють ребро |
| V4 | всі 4 вузли будь-якої грані |

**Чиста / брудна грань (для V4):**

| Тип батька | Грань чиста якщо не містить | Грань брудна якщо містить |
|-----------|----------------------------|--------------------------|
| T1 (кут Vi) | shell-індекс k=0 (= Vi) | k=0 (= Vi) |
| T2 (ребро Va–Vb) | k=0 (Va) і k=1 (Vb) | k=0 (Va) або k=1 (Vb) |

Алгоритм однаково застосовується і до чистих, і до брудних граней — різниця лише в тому які дочірні елементи отримають мітки з P.

**Параметр n2.** Додатково до n (кількість оболонок батька) можна задати n2 — кількість поділів що застосовуються до кожного дочірнього елемента при побудові онуків (T1→3n2−2, T2→2n2−1, T4→n2 онуків).

**Примітка.** Елемент з усіма 8 маркованими вузлами залишається нерафінованим — він вже рівномірно поділений.

Інтерактивна візуалізація: [`3D-node-propogation.html`](3D-node-propogation.html) — T1/T2-батько × V1/V2/V4, OrbitControls.

## §4.7 — ApplyTemplates (J direction)

Аналогічно §4.4. Після J-pass маркування з propagation можливі всі чотири шаблони:

| Вузлів | Шаблон |
|--------|--------|
| 1 | T1 |
| 2 (на одному ребрі) | T2 |
| 3 (L-форма на одній грані) | T3 |
| 4 (одна повна грань) | T4 |

## §4.8 — K direction refinement

K-pass є третім і останнім напрямком. Процедура повністю аналогічна J-pass:

1. **Expand**: до M додаються всі елементи рафіновані в I і J-pass
2. **MarkNodes (K)**: пари K-шарів, маркуються 4 вузли спільних граней включаючи нові вузли від I і J рефайнменту, з node propagation
3. **ApplyTemplates**: всі чотири шаблони можливі (T1, T2, T3, T4)

---

## §4.9 — Additional node marking requirements (3D)

В 3D можливі два особливих випадки маркування що потребують додаткових вузлів. Перевіряються під час MarkNodes (рис. 16, 17 статті).

### Умова 1 — Діагональне маркування (рис. 16)

На грані можуть виявитись позначеними лише два **діагональних** вузли (наприклад a і c, але не b і d). Такий шаблон не входить до набору рис. 5. Вирішення: додати обидва решта вузли (b і d), перетворюючи на **T4**.

### Умова 2 — Два суміжних T3 (рис. 17)

Якщо два сусідніх гекси обидва потребують T3-шаблону — два суміжних T3 є несумісними. Вирішення: позначити четвертий вузол одного з елементів, перетворюючи T3 → **T4**.

## Властивості алгоритму

| Властивість | Значення |
|------------|----------|
| Конформність | Гарантована — висячих вузлів немає |

| Паралельність | Мінімальна міжпроцесорна комунікація — лише парування шарів |
